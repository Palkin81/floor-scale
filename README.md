# Floor Scale

Автономная система из двух ESP32-устройств: напольных весов на XIAO ESP32-C6 с HX711 и отдельного экрана на ESP32. Сейчас основная функция весов — измерение и калибровка; экран пока служит прототипом сетевого интерфейса.

## Состояние проекта

Проект в разработке. Страницы настройки, приём и отправка зашифрованных Wi-Fi-учётных данных между устройствами добавлены в код, но передачу между двумя платами ещё нужно проверить на железе. Передача веса на экран и подключение реального дисплея запланированы.

Подробный список готовых задач, дальнейших этапов, ограничений и открытых решений находится в [плане проекта](plan.md). [Снимок состояния](project-snapshot.md) содержит дополнительный контекст и примеры фрагментов конфигурации; при расхождении с файлами прошивки ориентируйтесь на текущие конфигурации и план.

## Состав репозитория

- `floor-c6.yaml` — плата Seeed XIAO ESP32-C6, по умолчанию весы: HX711 на GPIO18 (D10, DOUT) и GPIO20 (D9, CLK).
- `floor-esp32.yaml` — плата ESP32 DevKit, по умолчанию экран; HX711 при включении: DOUT GPIO33, SCK GPIO32.
- `packages/` — весь код: `common.yaml` (сеть, роли, страница) и `device.yaml` (весы, экран, калибровка). Файл платы задаёт только плату и номера GPIO; роль и режим выбираются на странице «Система → Режим и роль», а схему подключения там же можно посмотреть.
- `lib/` — код HTTP-интерфейса, выбора сетевой роли, проверки Wi-Fi и расшифровки учётных данных.
- `ui/` — исходник веб-страницы устройств (`page.html`, стиль «Apple glass», разделы Главная / Сеть / Калибровка / Система) и скрипт `embed.py`, который вшивает её в `lib/ui_server.h`. Страницу правят в `ui/page.html`, затем запускают `python3 ui/embed.py` (проверка синхронности: `--check`).
- `make_blob.py` — вспомогательный скрипт формирования и отправки тестового зашифрованного блока.
- `plan.md` — план, журнал решений и известных рисков.
- `project-snapshot.md` — развёрнутый снимок состояния разработки.
- `web/` — CSS и собранный JavaScript ESPHome Web Server; текущие YAML-конфигурации используют встроенную страницу из `lib/ui_server.h`, а не эти файлы. Лицензионное уведомление для `web/www.js` находится в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Весы: подготовка и запуск

Нужны ESPHome с поддержкой ESP32-C6 и ESP-IDF, плата Seeed XIAO ESP32-C6, HX711 и тензоплатформа. Создайте `secrets.yaml` в каталоге конфигурации ESPHome. Потребуются следующие значения:

```yaml
wifi_ssid: "имя домашней сети"
wifi_password: "пароль домашней сети"
prov_ssid: "имя общей сети настройки"
prov_password: "пароль общей сети настройки"
espectre_encryption_key: "BASE64-КЛЮЧ"
```

Ключ `espectre_encryption_key` должен декодироваться из Base64 в 32 байта. Он используется для шифрования ESPHome API и OTA, а также для AES-256-GCM при передаче сетевых учётных данных. Не добавляйте `secrets.yaml` в Git. Образец с нужными ключами: `secrets.yaml.example`. В панели ESPHome те же значения лежат в меню ⋮ → «Секреты».

В каталог ESPHome нужно скопировать весь репозиторий: `floor-c6.yaml` или `floor-esp32.yaml`, папки `packages/` и `lib/` (там же `hxdet.h`, `devcfg.h` и остальные заголовки). Для C6 берите `floor-c6.yaml`, для ESP32 DevKit — `floor-esp32.yaml`: в панели у них разные имена, а прошить файл не от своей платы нельзя (чип не совпадёт).

Проверьте конфигурацию и прошейте плату:

```sh
esphome config floor-c6.yaml
esphome run floor-c6.yaml
```

Весы опрашивают HX711 с частотой 10 Гц, фильтруют показания медианой и EMA. Измерение начинается после превышения порога `trigger_kg` (по умолчанию 1,5 кг) и завершается, когда показания стабилизируются. Результат доступен на странице устройства и через сущности ESPHome API.

Для калибровки укажите массу известного груза, нажмите «Калибровать» и положите груз на платформу. Можно сохранить до пяти точек; промежуточные значения рассчитываются линейно. Кнопки «Обнулить» и «Сбросить точки» задают рабочий ноль и очищают кривую калибровки. Параметры фильтрации, пороги и тайм-ауты находятся в `substitutions` в начале `packages/device.yaml`.

## Экран и настройка Wi-Fi

Экран и весы равноправны: точку доступа поднимает тот, кто включился первым, её адрес у обоих `192.168.4.1`. Веб-интерфейс встроен в `lib/ui_server.h` и работает на порту 80. Он позволяет смотреть состояние, искать Wi-Fi, проверять пароль и открывать окно настройки на пять минут. Кнопка сброса пытается сбросить сеть на обоих устройствах; если сосед не отвечает, будет сброшено только текущее устройство.

Приём учётных данных реализован обработчиком `POST /prov` и доступен только в открытом окне настройки. После успешной проверки сети устройство шифрует креды AES-256-GCM и отправляет их соседу по HTTP. Код передачи добавлен, сквозной сценарий двух плат ещё требует проверки. Подробнее: [план проекта](plan.md).

Скрипт `make_blob.py` требует Python 3 и пакеты `requests` и `cryptography`. Он позволяет отдельно проверить приём одного зашифрованного блока на `/prov`.

```sh
python3 -m pip install requests cryptography
python3 make_blob.py "имя сети" "пароль" "BASE64-КЛЮЧ" 192.168.4.11
```
