# Напольные весы + экран: план проекта

Обновлено: 2026-10-23. Весы переведены на общую страницу и сетевую логику экрана (`lib/ui_server.h`, `lib/net_role.h`). Отправка кредов соседу пока не реализована ни на одном устройстве.

## Требования

- Весы встроены в кафельный пол, питание постоянное.
- Диапазон 1–200 кг.
- Давление > 5 кг (порог срабатывания 1.5 кг) включает дисплей, калибровка, приглашение, ожидание стабилизации, результат.
- Снятие веса: дисплей выключается через 10 с.
- Экран показывает вес, данные сети, статус связи с весами.
- Устройства равнозначны: настроил одно, настроились оба.
- Настройка сети через веб-страницу устройства: поиск сетей, ввод пароля, проверка подключения, отправка соседу.
- Креды по воздуху шифруются AES-256-GCM, ключ = `espectre_encryption_key` (тот же, что для API и OTA).
- Общая сеть настройки `prov_ssid`: ненастроенное устройство сначала ищет сохранённую домашнюю сеть, затем сеть настройки. Не нашло — поднимает сеть настройки как точку доступа.
- Доступ к устройству по IP и по `<имя>.local`.
- Веб-страница на русском, мобильная.

## Правила проекта

1. **Имена** (`id`, `name`, `friendly_name`, ключи substitutions, имена файлов): только латиница, цифры и `_`, без пробелов. Пример: `current_weight`.
2. **Русский** — в текстах, которые видит пользователь (страница, сообщения статуса).
3. **Секреты** — только в `secrets.yaml`, в чат не публикуются.
4. **Окно настройки** — приём кредов только в открытом окне. Счётчика версий нет.
5. **Файлы** — конфиги устройств в `/config/esphome/`, заголовки в `lib/`. Веб-морда встроена в `lib/ui_server.h`, отдельной статики (`web/`) нет.
6. **Межзадачный обмен**: httpd и цикл ESPHome не трогают состояние друг друга напрямую. Команды ставятся в очередь (`cmd_pending`), статус хранится в фиксированном буфере.

## Устройства

| Устройство | Плата | Назначение |
|---|---|---|
| Весы | XIAO ESP32-C6 (`seeed_xiao_esp32c6`) | HX711, измерение, калибровка, страница настройки |
| Экран | generic ESP32 (`esp32dev`) | заглушка со страницей настройки, позже дисплей |

## Журнал ошибок и правил работы

- Имена: `name` в REST-адресе становится URL, поэтому латиница без пробелов. Русский только в текстах сообщений и на странице.
- Стек `httpd` 12 КБ (4 КБ переполнялись при сканировании).
- `esp_http_server` подключается через `framework: advanced: include_builtin_idf_components` (в `include_builtin_idf_components` на верхнем уровне `esp32` ESPHome не принимает).
- `wifi_ssid()` в ESPHome 2026.10.0 не существует: имя сети берём через `esp_wifi_sta_get_ap_info`.
- Сканирование: компонент `wifi` ESPHome забирает результаты до нас, поэтому используем обработчик события ESP-IDF.
- Сканирование в режиме только AP даёт `ESP_FAIL`: переключаем в APSTA без подключения.
- `delay()` в `on_boot` блокирует цикл дольше 5 с — срабатывает watchdog. Задержки — только в `script`.
- Два HTTP-сервера не могут делить `ctrl_port`: страница использует `ctrl_port: 32769`.
- Команды калибровки и статус: httpd не трогает состояние ESPHome напрямую (очередь `cmd_pending` + `run_pending()` в цикле датчика).
- Файлы `lib/prov_crypto.h` и `lib/wifi_probe.h` лежат в `/config/esphome/lib/` (в рабочей копии здесь их нет, проверка ссылок по ним не делалась).
- Перед выдачей кода: сверять вызовы ESP-IDF с версией, проверять размеры стеков и буферов, проверять ссылки статическим скриптом (`id`, `ui::`, подстановки, кириллица в именах).

## Отложено: риск сохранения пробной сети

- Проверка пароля (`probe::try_connect`) вызывает `esp_wifi_set_config`, ESP-IDF по умолчанию пишет конфигурацию во флеш. После проверки сеть остаётся сохранённой, и после перезагрузки устройство подключается к ней без окна настройки.
- Планируемое исправление: перед проверкой `esp_wifi_set_storage(WIFI_STORAGE_RAM)`.
- Статус: отложено по решению пользователя. Касается обоих устройств (одинаковый код в `wifi_probe.h`).

## Известные риски

- **ESPHome 2026.10.0**: не подтверждены `save_wifi_sta`, `clear_sta`, `ap_timeout` (убран), вызовы ESP-IDF для сканирования и проверки, `on_connect` в `wifi`. Ошибки сборки — проверяем по документации версии.
- **AP+STA** — при проверке пароля телефон может потерять связь (канал роутера). Проверено на экране: страница не пропала.
- **Клиентское устройство**: если весы стали клиентом экрана, их страница доступна по IP в сети экрана (адрес в логе). Удобного способа найти её пока нет.
- **Гонка за роль точки** — не решена полностью.
- **Один ключ** для API, OTA и шифрования кредов. Утечка открывает все три.
- **Пароль на странице** отдаётся в браузер. Для домашней сети приемлемо.
- **Автонуль** на весах сейчас отсутствует (см. этап 0).
- **ESP8266** не рассматриваем: мало памяти, нет аппаратного AES, другой фреймворк.
